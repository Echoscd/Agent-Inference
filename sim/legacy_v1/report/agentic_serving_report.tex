\begin{abstract}
This report consolidates the agentic-serving project into a single mathematical
and implementation reference.  An agent program is a sequential chain of LLM
requests separated by tool calls.  Completing one request may reveal the next
request and grow the program prefix.  The scheduler chooses which waiting
requests to admit, which warm prefixes to keep in GPU KV memory, and which
prefixes to evict.  The main implemented algorithm is Bayes-Dual-Price, which
combines a Bayesian posterior over remaining program work with an online KV
shadow price.  The implementation also preserves the Bayesian Program Grade
policies and campaign-LP approximations from the repository.
\end{abstract}

\section{Model}

There are $n$ programs, all arriving at time zero.  Program $i$ consists of
\[
    R_{i,1},R_{i,2},\ldots,R_{i,K_i},
\]
where $K_i$ is a random request count with prior
\[
    \pi_i(k)=\Prb(K_i=k), \qquad k=1,\ldots,K_{\max}.
\]
The request count is independent of token lengths.  Request $R_{i,j}$ has
prefill length $P_{i,j}$ and decode length $D_{i,j}$.  When request $j$ is
revealed, its current pair $(p_i,d_i)$ is known in the simulator.  Future token
lengths are represented by means.

At stage $j_i$, the generated prefix length is
\[
    A_i=\sum_{\ell<j_i}(P_{i,\ell}+D_{i,\ell}).
\]
Let $h_i=1$ if the prefix is warm in GPU KV cache and $h_i=0$ if it was evicted.
The current request service time is
\[
    \tau_i(h_i)=\alpha\left(p_i+(1-h_i)A_i\right)+d_i.
\]
The peak active KV footprint is
\[
    q_i=A_i+p_i+d_i.
\]

Active requests are non-preemptive.  Prefill is non-blocking and every
decode-ready active request receives one token per decode step.  Peak
reservation gives the feasibility condition
\[
    \sum_{i\in\mathcal A_t} q_i+\sum_{i\in\mathcal H_t} A_i\le M,
\]
where $\mathcal A_t$ is the active set and $\mathcal H_t$ is the set of held
inactive warm prefixes.

\section{Posterior Quantities}

At stage $j_i$, the event $K_i\ge j_i$ is known.  Define remaining request count
\[
    R_i^{(j_i)}=K_i-j_i+1.
\]
Then
\[
    \Prb(R_i^{(j_i)}=r)
    =
    \frac{\pi_i(j_i+r-1)}{\sum_{k\ge j_i}\pi_i(k)}.
\]
The expected remaining work used by Bayes-Dual-Price is
\[
    \mu_i=\tau_i(h_i)+\left(\E[R_i^{(j_i)}]-1\right)\bar s,
    \qquad
    \bar s=\E[\alpha P+D].
\]
The projected future KV footprint is
\[
    \bar q_i=q_i+\frac12\left(\E[R_i^{(j_i)}]-1\right)\bar g,
    \qquad
    \bar g=\E[P+D].
\]

\section{Implemented Algorithms}

\subsection{Commit-Many}

Commit-Many starts as many programs as possible.  Once a program has started,
its continuation is prioritized until termination.  At each decision epoch:
\begin{enumerate}
    \item admit committed waiting programs first;
    \item use remaining memory to start new programs;
    \item hold committed warm prefixes if residual memory permits;
    \item evict warm prefixes that do not fit.
\end{enumerate}

\subsection{Least-Rounds}

Least-Rounds prioritizes the smallest number of completed requests.  Waiting
programs are sorted by $(j_i-1,\tau_i,\text{reveal order})$ and admitted while
peak reservation remains feasible.  Residual memory holds prefixes in the same
order.

\subsection{Current Density}

Current Density ignores the request-count prior and uses only the revealed
current request:
\[
    \operatorname{score}_i^{\rm cur}=\frac{1}{q_i\tau_i(h_i)}.
\]
It is a strong diagnostic baseline because current decode length is known in
the simulator.

\subsection{Bayesian Program Grade}

For a campaign that serves at most $m$ future requests, define
\[
    P_i(m)=\Prb(R_i^{(j_i)}\le m),
\]
and
\[
    B_i(m)=\sum_{\ell=1}^m s_{i,\ell}\Prb(R_i^{(j_i)}\ge \ell),
\]
where $s_{i,1}=\tau_i(h_i)$ and $s_{i,\ell}=\bar s$ for $\ell\ge2$.  The grade is
\[
    g_i=\max_{m\ge1}\frac{P_i(m)}{B_i(m)}.
\]
The implemented admission score is $g_i/q_i$.  Warm prefixes are held by
decreasing $g_i$.  The warm-marginal variant uses $g_i/(p_i+d_i)$ for warm
requests and $g_i/q_i$ for cold requests.

\subsection{Current Dual Descent}

This commitbase baseline uses value $v_i^{\rm cur}=1/\tau_i$ and a single
memory price:
\[
    \Delta_i=v_i^{\rm cur}-\lambda_t q_i.
\]
Positive-margin requests are packed by decreasing $\Delta_i/q_i$.  The price is
updated from desired current memory pressure.

\subsection{Bayes-Dual-Price}

Bayes-Dual-Price is the main LP+Bayesian algorithm from
\texttt{bdp\_final\_project\_commitbase}.  It uses
\[
    v_i=\frac{1}{\tau_i(h_i)\mu_i}
\]
and the reduced run margin
\[
    \Delta_i^{\rm run}=v_i-\lambda_t\bar q_i.
\]
Only positive-margin requests are admitted, packed by decreasing
$\Delta_i^{\rm run}/q_i$.

For a warm inactive prefix, the hold margin is
\[
    \Delta_i^{\rm hold}=\frac{\alpha A_i}{\mu_i}-\lambda_tA_i.
\]
Positive-margin holds are packed after run admissions.

The online price update is
\[
    \lambda_{t+1}
    =
    \left[
      \lambda_t+\eta_t\left(\frac{D_t}{M_t}-1\right)
    \right]_+,
\]
where $D_t$ is the projected footprint of positive-margin candidates and
$M_t$ is free memory after protecting active requests.

\subsection{Two-Price Mu Variant}

The repository images propose testing $v_i=1/\mu_i$ and separating present KV
from anticipated future growth.  The implemented variant is
\[
    \Delta_i^{\rm run}
    =
    v_i-\lambda_t q_i-\nu_t(\bar q_i-q_i),
\]
and
\[
    \Delta_i^{\rm hold}
    =
    (v_i^{\rm warm}-v_i^{\rm cold})-\lambda_tA_i.
\]
It is included as a documented variant rather than the main claim.

\subsection{Campaign-LP Surrogate}

For each waiting program and campaign option $c=(i,m)$, define completion value
and average KV footprint
\[
    v_{ic}=\frac{P_i(m)}{B_i(m)},\qquad
    \bar q_{ic}=\frac{\mathcal A_i(m)}{B_i(m)},
\]
where $\mathcal A_i(m)$ is expected KV-time area.  The resolving LP is
\[
\begin{aligned}
\max_{x,z}\quad
&\sum_{i,c}v_{ic}x_{ic}+\sum_i h_i z_i\\
\text{s.t.}\quad
&\sum_{i,c}q_i x_{ic}+\sum_i A_i z_i\le M_t,\\
&\sum_{i,c}\bar q_{ic}x_{ic}+\sum_i A_i z_i\le M_t,\\
&\sum_c x_{ic}+z_i\le1,\qquad 0\le x_{ic},z_i\le1.
\end{aligned}
\]
The implementation extracts peak and future dual prices, then restores
pathwise feasibility by greedy run-then-hold packing.

Preserved LP policies are: full LP update, solve-once, selective update,
infrequent resolving, online LP dual descent, short-horizon MPC, dual
threshold, and fixed campaign KV-area grade.

\section{Preempt and Delete Metrics}

The simulator keeps active requests non-preemptive.  The requested preempt
metric is therefore defined at the inactive-prefix level:
\[
    \text{preempt event} =
    \text{a warm waiting prefix is held in memory but not admitted}.
\]
The delete ratio is
\[
    \frac{\text{warm-prefix evictions}}
    {\text{warm-prefix holds}+\text{warm-prefix evictions}}.
\]
The CSV output also includes unique preempted request stages and their ratio to
completed requests.

\section{Experiment Setup}

The cleaned simulator uses decode-heavy profiles rather than the earlier short
decode lengths:
\[
\begin{array}{c|cc}
\text{profile} & \E[P] & \E[D]\\
\hline
\text{prefill-heavy} & 160 & 100\\
\text{balanced} & 120 & 150\\
\text{decode-heavy} & 80 & 200
\end{array}
\]
Memory is set to $M=fq_{\max}^{\rm obs}$.  The quick comparison reported below
uses $f\in\{5,10,15,20\}$ and increases the injected program count with memory:
\[
    (f,n)\in\{(5,170),(10,320),(15,480),(20,640)\}.
\]
The quick prior is \texttt{quick10}, with realized mean request count about
$10$ rounds per program.  This avoids the earlier artifact where large $f$
became cache-slack because the number of submitted programs was fixed.  The
larger standard and stress presets remain at $f\in\{1,2,4\}$ for tighter stress
testing.

descent is the more conservative memory-pressure policy.

\section{Implementation Guidance}

The production path in vLLM should begin with Bayes-Dual-Price or LP dual
descent, not full synchronous LP re-solving.  The scheduler needs only a small
program-level metadata layer, access to block-manager prefix residency, a
conservative estimate of current request footprint, and a request-boundary
policy hook.  Full LP resolving is best used as an offline benchmark or a
background price-correction routine.
